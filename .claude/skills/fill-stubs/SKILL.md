# fill-stubs: 빈 개념 노트 채우기 + 기존 노트와 연결

DontPanic 볼트의 `Concepts/` 폴더에서 제목만 있고 내용이 없는 노트를 찾아, 웹 서치로 조사한 내용으로 채운다. 그리고 밀접한 기존 노트의 `## 연결` 섹션에 새 노트로 가는 링크를 덧붙여 양방향으로 연결한다. **볼트 원본에 직접 쓴다** (다음 sync 주기에 위키에 자동 반영됨).

볼트 경로: `/Users/giy/Library/Mobile Documents/iCloud~md~obsidian/Documents/DontPanic`

## 인자

- (없음): 대화형. 스텁 목록을 보여주고 최대 5개 처리.
- `<노트 이름>`: 그 노트만 처리.
- `--auto`: **헤드리스 모드** (launchd → `scripts/fill-stubs.sh` → `claude -p`). 사용자에게 질문하지 않고 스텁 최대 5개를 바로 처리. 보고는 stdout에 간결한 텍스트로 (로그 파일에 기록됨).
- `--list`: 스텁 후보만 출력하고 종료 (쓰기 없음).
- `--no-backlink`: 5단계(기존 노트 역방향 연결) 생략.

## 절차

### 1. 스텁 탐지
`Concepts/` 폴더에서 후보 찾기:
```bash
find "$VAULT/Concepts" -name "*.md" -size -300c
```
각 후보를 Read로 확인해 스텁 여부 판정: 프론트매터를 제외한 실질 본문이 80자 미만이거나 위키링크만 있으면 스텁. 이미 `ai-generated: true`인 파일은 제외.

사용자가 특정 노트를 지정했으면 그것만, 아니면 목록을 보여주고 **한 번에 최대 5개**까지 처리 (사용자가 명시적으로 더 요청하면 초과 가능). `--auto`에서는 목록 확인 없이 파일 수정 시각이 오래된 것부터 5개.

### 2. 조사 및 작성 (병렬 가능)
여러 개를 처리할 때는 **에이전트 최대 5개 병렬** (스텁 1개당 1에이전트, general-purpose). 각 에이전트에게:
- 개념 이름(파일명)과 기존 파일 내용(보존할 위키링크 포함) 전달
- WebSearch/WebFetch로 조사 (한국어+영어 검색 병행, 신뢰할 만한 출처: 학술 자료, 사전, 위키백과, 전문 아티클)
- 볼트 Concepts의 전체 파일 목록 전달 → **볼트에 실존하는 노트로만 위키링크** (깨진 링크 금지)
- 결과로 **"밀접 관련 기존 노트" 목록(최대 5개)**도 함께 반환받는다. 5단계에서 사용.

### 3. 노트 형식
이 볼트는 한국어 인문학/미디어이론 연구 볼트다. 볼트 자체 템플릿(`templates/tpl_concept.md`) 구조를 따른다:

```markdown
---
type: concept
tags: [관련, 태그]
ai-generated: true
ai-generated-date: YYYY-MM-DD
isRead: false
sources:
  - https://출처1
  - https://출처2
---

# 노트
(개념의 핵심을 한국어로 2단락, 합쳐서 500~700자. 1단락: 정의와 제안자/기원. 2단락: 왜 중요한지, 이 볼트 맥락(인문학/미디어이론/예술)에서의 의미.
학술적이되 자기 말로 풀어쓴 톤. 어원·연대·인용은 핵심적인 것 1~2개만.)

## 관련내용
(**굵은 소제목** + 2~3문장 형식의 항목 3~4개. 핵심 논점, 주요 이론가, 논쟁. 각 항목 250자 이내.)

## 연결
(기존 파일에 있던 위키링크는 반드시 보존 + 볼트에 실존하는 관련 노트 링크 추가. 최대 6개, 각 한 줄 설명.)

## 열린 질문
(이 개념에서 파생되는 탐구 질문 2개, 각 1~2문장.)
```

**독자와 톤 (2026-09-09)**: 이 위키는 사용자가 **심심할 때 들어가서 읽으며 공부하는 용도**다. 논문이 아니라 잘 읽히는 개념 해설을 쓴다. 한 문장은 짧게(40자 안팎), 한 단락에 한 가지 생각. 전문용어는 처음 나올 때 괄호 없이 한 구절로 풀어 준다. 인명·저작·연도 나열, 원어 병기 남발, 세미콜론·긴 삽입구는 피한다. 첫 문장만 읽어도 "이게 뭔지" 알 수 있게 쓴다.

**분량 상한 (2026-09-09 사용자 요청: "요점만 간략하게")**: 프론트매터 제외 본문 총 **1,800~2,500자** (파일 크기로는 약 4~5.5KB). 이보다 길면 줄여서 저장한다. 망라보다 요점. 하위 에이전트에게 이 상한을 프롬프트에 그대로 전달할 것.

**필수 프론트매터 `isRead: false`** (2026-09-10 사용자 요청): 사용자가 읽었는지 옵시디언 체크박스 속성으로 표시하기 위한 것. AI가 새로 채우는 노트에는 항상 `isRead: false`를 넣는다. 기존 프론트매터에 `isRead`가 이미 있으면 그 값을 보존한다. 역방향 링크만 추가하는 기존 노트(5단계)에는 넣지 않는다.

### 4. 쓰기 직전 안전 확인
파일에 쓰기 **직전에 반드시 다시 Read**해서 여전히 스텁인지 확인. 그 사이 사용자가 내용을 채웠으면 skip (iCloud 다중 기기 편집 충돌 방어). 기존 프론트매터가 있으면 키를 보존하며 병합.

### 5. 기존 노트에 역방향 연결 (`--no-backlink`가 아니면 항상)
새로 채운 노트 X에 대해, 2단계에서 받은 "밀접 관련 기존 노트" 각각(Y)에 대해:
- Y가 이미 `[[X]]`를 포함하면 skip.
- Y를 Read하고, **`## 연결` 섹션에만** 한 줄 추가: `- [[X]] — (X와 Y의 관계 한 줄, 한국어)`. 다른 섹션·본문·프론트매터는 절대 수정하지 않는다.
- Y에 `## 연결` 섹션이 없으면 `## 열린 질문` 앞(없으면 파일 끝)에 `## 연결` 섹션을 새로 만들어 추가.
- 한 스텁당 역방향 링크는 **최대 3개**, 정말 밀접한 것만. 단순히 같은 분야라는 이유로는 추가하지 않는다.
- 추가한 줄에 `<!-- ai-linked YYYY-MM-DD -->` 주석을 붙여 나중에 찾거나 되돌릴 수 있게 한다.
- Y가 사용자가 직접 쓴 노트여도 허용됨 (사용자 승인: 2026-09-09).

### 6. 보고
처리 완료 후 보고: 채운 노트 목록(개념별 한 줄 요약), 역방향 링크를 추가한 기존 노트 목록(Y ← X 형태), skip한 것과 이유, 사용한 주요 출처. AI가 채운 노트는 옵시디언에서 `ai-generated` 태그로, 자동 추가된 링크는 `ai-linked` 문자열로 검색 가능함을 안내. `--auto`에서는 보고를 짧은 텍스트 요약으로 stdout에 출력하고 종료.
